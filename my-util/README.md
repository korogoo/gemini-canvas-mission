## 앱 이름: 🍒정신체리 (Mind Cherry)
## 카테고리: 유틸리티 앱

### 배포 링크
https://gemini.google.com/share/8a5c074f186b

### 이 앱을 만든 이유
- 어떤 문제/불편함을 해결하려고 했나요?
> 우테코 데일리 회고를 작성할 때 하도 진행한 일이나 발생한 사건이 많아서 "오늘은 무엇을 했다"는 식의 단순 사실 나열에 그치는 경우가 많았습니다.  
> 이는 도전에 집중한 자기 성찰적 회고를 작성하기가 어려웠습니다.

- 이 앱을 언제, 어떻게 사용할 건가요?
> 일일 학습이나 프로젝트 구현을 마친 후, 본인이 작성한 초안 회고록을 앱에 붙여넣습니다.  
> AI가 던지는 날카로운 비평과 질문에 답하며 회고의 질을 높이고,  
> "왜", "도전과 시도", "자기 성찰"에 집중할 수 있도록 돕습니다.

<br/><br/>

### 주요 기능

**문맥 기반 실시간 분석**
> 작성된 글을 분석하여 '단순 사실', '성찰이 담긴 문장', '비평이 필요한 구간'을 구분합니다.

**정신체리 비평**
> 시니어 코치의 페르소나를 가진 AI가 안일한 생각을 날카롭게 지적(팩폭)하여 정신을 번쩍 들게 합니다.

**5단계 심층 리파인먼트 인터뷰**
> 비평에 그치지 않고, 글 전체의 맥락을 관통하는 5개의 질문을 통해 사용자의 사고를 강제로 확장시킵니다.

**최종 분석 리포트 생성**
> 인터뷰 답변을 종합하여 [핵심 깨달음 / 도전 의식 / 개선 방향]을 개괄식으로 정리해 줍니다.

<br/>

### AI 기능
**Gemini 2.5 Flash**
- > 문장 단위의 단순 패턴 매칭이 아니라 글 전체의 맥락을 파악하여 '개발자로서 더 고민했어야 할 지점'을 찾아냅니다.

**구조화된 데이터 추출**
> 사용자의 입력을 분석하여 JSON 형식으로 변환, UI 요소(하이라이트 색상, 게이지 점수 등)와 연동하여 시각적인 피드백을 제공합니다.

## AI 사용 일지

### 1. 초기 프롬프트
```text
제목: 우테코 8기 회고 굴착기 - "Fact to Challenge Driller"

1. 앱의 목적 및 페르소나

목적: '오늘 무엇을 했다'라는 단순 사실(Fact) 나열 위주의 회고를 분석하여, 그 이면에 숨겨진 '왜(Why)'와 '어떻게(How)'를 끌어내고 도전 의식을 고취함.

페르소나: 부드러운 위로보다 날카로운 통찰을 선호하는 우테코 시니어 코치. 사용자가 안일하게 작성한 문장을 귀신같이 찾아내어 뒤통수를 때리는 질문을 던짐.



2. 핵심 기능 로직 (JavaScript)

[Sentence Classifier]: 입력된 텍스트를 문장 단위로 분리하고, 정규표현식을 사용하여 다음 두 가지로 분류함.

Fact(사실): "~했다", "~구현했다", "~배웠다", "~사용했다"로 끝나는 단순 나열형 문장.

Insight(통찰): "~라고 생각했다", "~때문에 고민했다", "트레이드오프", "실패했다", "의문이 들었다" 등 사고의 과정이 포함된 문장.

[Comfort Zone Score]: (Insight 문장 수 / 전체 문장 수) * 100 점수를 계산하여 시각화. 40점 미만일 경우 "안일함 경보" 발령.

[The Drilling Engine]: Fact로 분류된 문장 중 하나를 랜덤하게 선택하거나 사용자가 클릭하면, 해당 문장의 키워드를 기반으로 3단계 심층 질문 생성:

1단계 (기술적 근거): "그 기술을 선택한 게 최선이었나? 단순히 익숙해서 선택한 것 아닌가?"

2단계 (트레이드 오프): "그 선택으로 인해 포기해야 했던 가치는 무엇인가? (예: 시간, 성능, 가독성 등)"

3단계 (확장성 및 도전): "만약 요구사항이 10배 까다로워진다면, 지금 네가 한 방식은 무용지물이 되지 않을까? 어떻게 대비할래?"



3. UI/UX 구성 (HTML/CSS)

Layout: 좌우 2분할 대시보드.

좌측 (Input Zone): 회고록 원본을 붙여넣는 넓은 텍스트 영역.

우측 (Analysis Zone): 실시간 분석 결과(Fact vs Insight 비율)와 앱이 던지는 '공격적인 질문'이 나타나는 영역.

Visual Effect:

단순 Fact 문장에는 빨간색 밑줄(Wave underline) 표시.

Insight 문장에는 청록색 형광펜 효과 표시.

질문이 나타날 때 화면이 미세하게 흔들리는(Shake) 효과로 '뒤통수 타격'을 시각화.

Gauge: 상단에 '사고의 깊이(Thinking Depth)' 게이지를 두어, 질문에 답변할수록 게이지가 차오르게 함.



4. 최종 결과물 생성

모든 질문에 답변하면, [기존 사실 + 추가된 고민 + 내일의 도전 과제]를 조합하여 **"진짜 성찰이 담긴 우테코식 회고록"**을 마크다운 형식으로 자동 생성하고 복사 버튼 제공.



5. 기술 제약 및 문구

제약: 외부 라이브러리 없이 순수 HTML/CSS/JS로 작성할 것.

필수 포함 문구: "안일함은 성장의 적입니다.", "사실 나열은 일기장에나 하세요.", "진짜 도전을 기록할 준비가 되었나요?"

이 요구사항을 바탕으로 즉시 실행 가능한 index.html 코드를 작성해줘.
```

### 2. 프롬프트 개선 과정

#### 문제점
> 초기에는 정규표현식 기반으로 "~했다"를 찾았으나, "셔틀을 탔다"와 같은 정말 일반적인 사실 기술과 "Redux를 썼다" 와 같은 개발 사실 기술을 구분하지 못해 기술적 근거가 필요 없는 일상 문장에도 비평이 가해지는 문제가 있었습니다.

#### 수정 방향
> 문장 단위 분류 로직을 Gemini AI를 연동하여 '기술적 사실'과 '일반적 사실'을 구분하도록 프롬프트를 고도화했습니다.

#### 반복 횟수
> UI 레이아웃 변경(사이드바 -> 가로형 -> 전체 뷰 전환), 테마 변경(다크모드 -> 우드 톤), 로직 수정 등 약 10회 이상의 반복을 거쳐 완성되었습니다.

<br/>

### 3. 효과적이었던 프롬프팅 전략

**페르소나 부여**
> '독설가 시니어 코치', '정신체리'와 같은 구체적인 캐릭터를 부여했을 때 응답의 톤앤매너가 일관되고 흥미롭게 유지되었습니다.

**JSON 스키마 정의**
> AI에게 응답을 요구할 때 명확한 JSON 구조를 지정하여 앱의 UI와 로직이 깨지지 않고 안정적으로 통신하게 했습니다.

**비동기 뷰 전환**
> "분석 버튼 입력 시 인풋창을 숨겨라"와 같이 상태에 따른 UI 변화를 구체적으로 요청하여 사용자 경험을 직관적으로 만들었습니다.

<br/>

### 4. 배운 점

**UI의 단순화**
> 입력창이 너무 크면 분석 결과에 집중하기 어렵다는 점을 깨달았습니다. 작업 단계에 따라 화면을 전환(Switch View)하는 것이 훨씬 몰입감 있는 경험을 제공한다는 것을 배웠습니다.

**가독성의 디테일**
> 자간(letter-spacing)과 행간(line-height) 같은 아주 작은 디자인 디테일이 비평글의 '압박감'과 '가독성'에 큰 영향을 준다는 것을 확인했습니다.

<br/>

### 5. 리뷰어에게 피드백 받고 싶은 포인트

> AI가 생성하는 5단계 질문이 실제 개발적 성장을 이끌어낼 만큼 충분히 날카로운지, 혹은 더 깊은 기술적 담론을 이끌어내기 위한 프롬프트 개선안이 있을지 궁금합니다.
